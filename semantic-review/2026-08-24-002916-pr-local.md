# 已认证 WSS 会话的撤销边界与终态投影

Worker 将设备 credential 校验放在 WSS 握手，并把每台设备的连接、pending 请求与 timeout 放进同一个 Durable Object。请求终态先持久化到 DO，再投影到 D1，HTTP 轮询通过 D1 索引路由回对应 DO。默认离线、超时、断线与协议错误都会拒绝，但 credential 的撤销/轮换没有使已建立的会话失效，攻击者可在旧会话上继续提交 `allow`。Watch for: **confirmed — 设备状态或旧 credential 到期后，已建立的 WebSocket 仍可授权新请求，违背撤销与轮换的安全边界。**

**Verdict**: NEEDS_CHANGES

## High-level view

认证只在公开 Worker 的升级请求执行一次；DO 的 socket attachment 只保存 `deviceId` 和 `sessionId`。因此 D1 的 `status`、credential version 或旧 credential grace 结束均不会影响存活连接，后续匹配 session 与 pending 的 decision 可以形成 `allow`。

DO 的存储是审批终态的事实来源，D1 是轮询索引和审计投影。终态已写入 DO 后若 D1 batch 失败，当前代码不保留待重试标记也不设置重试 alarm，两个存储将永久不一致。

1. **严重：撤销或轮换后存活的 WSS 会话仍可 allow** — **confirmed**：握手后的 decision 路径不再检查 D1 device 状态、credential version 或 previous-credential 到期时间。将认证版本写入 attachment/state，并在创建请求及处理 hello/decision 时重新确认设备仍为 active 且版本有效；更可靠的方案是在 rotate/revoke 时向该设备 DO 发失效命令，关闭所有旧版本 socket 并拒绝 pending。

## 严重：撤销或轮换不能收回已建立的授权通道

`connectDevice` 在 `src/index.ts:50-59` 用 D1 的 hash 和 active 状态认证 upgrade，但传给 DO 的身份只是一条已在边界处认证的设备 header。`SocketAttachment` 只包含 device/session，`webSocketMessage` 在 `src/passport-relay.ts:92-102` 接受匹配消息的 `decision: "allow"`，没有重新读取 D1 或比较 credential version。

旧 credential 的持有者只要在 grace 到期前建立连接，或设备被置为 `revoked` 前建立连接，就能保持当前 session 并在之后的新请求上继续 `allow`。`handleHello` 只在新 hello 到来时替换当前 session，不能收回现有 socket。认证有效期必须覆盖整个会话；轮换/撤销时应使 DO 的旧版本连接和 pending 请求立即失效、关闭并拒绝。

## 高：终态存储成功而索引/审计失败会永久分叉

`finishPending` 在 `src/passport-relay.ts:235-253` 先写入 DO state/outcome、删除 alarm，再调用 D1 的 `writeTerminalAudit`。`src/db.ts:44-54` 的 batch 失败时，DO 已是 allow 或 deny，`approval_requests` 仍为 pending，且没有 outbox、重试状态或后续 alarm；离线分支的 `storeOutcome` 也一样。

轮询会转发到 DO 并可能返回 `allow`，但请求索引、审计记录和依赖 D1 终态的操作永久遗漏。将终态及“D1 待投影”作为一次 DO state 写入，D1 失败时安排 retry alarm，成功后才清除同步标记。

## 中：default-deny 生命周期缺少可执行验证

工程只定义了 typecheck 脚本，搜索不到测试文件或测试命令。认证撤销、hibernation 后 attachment 重建、alarm、D1 短暂失败与 close/decision 竞争都依赖跨存储异步行为；为 DO 增加集成测试并注入可失败的 D1 层，断言未知、失效或过期身份只会产生 deny，且投影最终收敛。

</details>
